# Sprint 4 — PO

**Ведущая роль: PO (Product Owner).** Фокус спринта — анализ исходного продукта Figma Make, выявление разрыва между макетом и Android-версией, формулирование требований и приоритизация аналитических возможностей. Изменения Compose-кода в этом спринте сопровождают реализацию согласованного объёма.

## Цель
Сверить Android-приложение с исходным проектом Figma Make, определить обязательную логику аналитики и зафиксировать критерии её приемлемой реализации.

## Выполнено
- Изучены экранная структура, модель Discipline/Grade, фильтры, типы работ и серверные операции Figma Make.
- Зафиксированы ограничения архитектуры: исходник использует Next.js/Payload CMS, Android-приложение — локальную Room DB.
- Приоритизированы функции аналитики: график последних оценок, выбор дисциплины и калькулятор следующей оценки для достижения целевого среднего балла.
- Сформулировано поведение для случая, когда цель нельзя достичь одной следующей оценкой.
- Сопровождающая реализация: аналитика вынесена в отдельный Compose-компонент, добавлены график и калькулятор.
- Сохранена Room-архитектура Android-приложения; интеграция с Payload API не выполнялась из-за отсутствия настроек сервера и авторизации.

## Критерии приёмки
- Пользователь может просматривать динамику оценок.
- Пользователь может выбрать дисциплину для анализа.
- Пользователь может задать желаемый средний балл и получить расчёт требуемой следующей оценки.
- Если цель недостижима одной оценкой, интерфейс сообщает об этом.

## Не входит в этот спринт
Фильтрация/сортировка журнала, редактирование и удаление оценок в UI, CRUD дисциплин, профиль и полное пиксельное совпадение.
