# Спринт 2. Модель данных и локальное хранение

**Цель:** реализовать локальное хранение дисциплин и оценок в Room/SQLite, CRUD-операции и подготовить данные для проверки.

## Модель данных

### Discipline
| Поле | Тип Kotlin | Назначение |
|---|---|---|
| id | Long | Первичный ключ, генерируется БД |
| name | String | Название дисциплины |
| teacherName | String? | Преподаватель, необязательное поле |

### Grade
| Поле | Тип Kotlin | Назначение |
|---|---|---|
| id | Long | Первичный ключ, генерируется БД |
| disciplineId | Long | Внешний ключ на Discipline.id |
| value | Int | Оценка от 2 до 5 |
| date | String | Дата в формате ISO-8601: yyyy-MM-dd |
| workType | String | Тип учебной работы |
| comment | String? | Необязательный комментарий |

**Связь:** одна дисциплина содержит много оценок (1:N). Удаление дисциплины настроено с каскадным удалением связанных оценок, чтобы не оставлять записи-сироты.

## Слой хранения
- `DisciplineEntity`, `GradeEntity` — Room Entity;
- `DisciplineDao`, `GradeDao` — запросы и CRUD;
- `StudentDatabase` — RoomDatabase;
- `StudentRepository` — единая точка доступа к DAO;
- `DatabaseSeeder` — заполнение демонстрационными данными при первом создании БД.

## Проверки
1. Создание дисциплины и получение её по id.
2. Добавление оценки и получение оценок дисциплины.
3. Изменение значения и комментария оценки.
4. Удаление оценки.
5. Каскадное удаление оценок вместе с дисциплиной.
6. Проверка запрета оценки вне диапазона 2–5.
7. Повторное чтение после закрытия и повторного открытия базы.

## Решение по данным
Оценки имеют одинаковый вес. Средние баллы не сохраняются в БД, а рассчитываются из записей, чтобы не возникало рассогласования после изменения/удаления оценки. Дата хранится как ISO-строка; сортировка по ней лексикографически совпадает с хронологической.

## Результат спринта
Реализованы сущности, связь 1:N, DAO, база Room, репозиторий и тестовые данные. Для проверки постоянства хранения необходимо запустить приложение/инструментальные тесты на Android-устройстве или эмуляторе.
